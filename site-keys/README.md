# 便签本 · Sticky

一个极简的 Chromium MV3 扩展，两个模块、打开就填、输入即存：

- **便签**：小卡片按 n*n 瀑布网格铺开，一眼扫完；点开卡片才编辑。适合地址、账号、密码、命令这类短信息。
- **记事本**：一整页沉浸式编辑器，顶部或左侧切换文件。适合长文本。

纯本地 · 明文 · 不联网 · 不同步 · 无服务端 · 无需任何口令。
设计稿见 [`design/mockup.html`](./design/mockup.html)，规格见 [`SPEC.md`](./SPEC.md)，拆票与验收见 [`docs/TICKETS.md`](./docs/TICKETS.md)。

> **v4.0 是按已确认设计稿的重做**；**v4.1 新增记事本导入 `.txt`**；**v4.2 把存储改成按条分键 + 增量写入**（旧整库自动迁移、输入 250ms 节流、解除 10 MB 配额、写入失败持久提示）；**v4.3 新增网页选中文本右键「存为便签」**。v1 加密账号库、v2 按域名归组账号库、v3 单列大卡片便签本全部作废。

## 安装

```bash
cd site-keys
npm install
npm run build
```

打开 `chrome://extensions`（Edge 为 `edge://extensions`）→ 开启「开发者模式」→「加载已解压的扩展程序」→ 选 **`site-keys/dist/`**（选 `site-keys/` 也行，根目录清单已转发）。

改过代码后记得在扩展卡片上点「重新加载」。扩展图标由 `npm run icons` 生成（便签纸造型，同时刷新 [`design/icon-preview.html`](./design/icon-preview.html) 里内嵌的预览副本）；Chrome 会缓存图标，换图后若工具栏仍显示旧图，移除扩展再加载一次即可。

## 怎么用

**打开**：点工具栏图标，或按 `Alt+Shift+S` 打开侧栏；顶栏右侧「全屏打开」切到全屏页。

**切换模块**：顶栏分段控件「便签 / 记事本」，括号里是各自的条数。刷新后默认回到便签。

### 网页上选中文本，右键存为便签

在任意网页里**选中一段文字 → 右键 → 「存为便签」**，一次选中就生成一张新便签：

- 标题自动取选中内容的第一行（最多 24 字），正文原样保存，只去掉首尾空白；不弹窗、不追问、不记录网址。
- 新便签排在便签列表最前。侧栏 / 全屏页开着的话会立刻刷出来并提示「已存为便签」；没开也会存好，下次打开自然在。
- 纯空白选中不会建空便签；连续右键多次会依次存成多张，不会互相覆盖。
- 只需要 `contextMenus` 权限：浏览器在右键时直接把选中文本交给扩展，**不注入脚本、不读网页 DOM、不需要站点访问权、不联网**。浏览器自带的 `chrome://` 受保护页面不会出现该菜单项。

### 便签模块

- **看**：小卡片网格，侧栏 2 列 / 中宽 3 列 / 全屏 4 列；卡片只显示标题和最多 4 行摘要。
- **编辑**：**点卡片**弹出详情浮层，标题 + 正文直接改，**输入即存、没有保存按钮**。
- **操作**：鼠标移到卡片上，右上角淡出「复制全文 / 复制密码 / ⋯」；「⋯」里还有编辑和删除。正文含 `密码：xxx` / `password: xxx` 时才有「复制密码」，只复制值，不强制格式。
- **新建 / 清空**：顶栏搜索框右边的「＋」新建（窄栏收成一个方形按钮），底部「清空全部便签」需二次确认，且**不影响记事本里的文档**。
- **找**：搜索框匹配标题和正文，空格分隔多词（AND）。

### 记事本模块

- **全屏**：左侧 240px 文件栏列出所有文档，当前项高亮；右侧整页无边框书写区，顶部只有文件名、字数、更新时间和「复制全文」。
- **侧栏**：文件栏收成顶部下拉，点开可切换 / 新建 / 删除文档；编辑区仍占满整页。
- **编辑**：标题 + 一大块正文，`输入即存`。新建文档自动切过去并聚焦标题。
- **导入 txt**：文件栏（全屏）或文档下拉（侧栏）里的「导入 txt」，**一个 txt = 一篇新文档**，文件名自动作标题，正文原样写入；可以一次多选，选完即入库，不会追加或覆盖当前文档。
- 首次打开**没有预置文档**，点「＋ 新建文档」开写。便签和记事本的数据完全独立，没有互相转换。

### 导入 txt 的细节

| 项 | 行为 |
|---|---|
| 支持格式 | 只收 `.txt`（`accept=".txt,text/plain"`），**不收 `.md`、不渲染 Markdown** |
| 编码 | 自动识别 UTF-8（含 BOM）、GBK/GB18030、UTF-16LE/BE（含 BOM 与无 BOM 的 NUL 特征）；BOM 会剥掉，正文不做任何改写 |
| 标题 | 文件名去掉 `.txt`（Windows / Unix 路径都不会带进来）；空白名兜底「未命名文档」，超长截断 80 字 |
| 数量 / 体积 | 一次最多 20 个、单个 ≤ 1 MB；超限、非 txt、解码失败逐个跳过并提示原因，**不阻塞其他文件** |
| 写入 | 整批只写一次盘；导入完自动切到第一篇；同名文件不去重、不阻止 |
| 权限 | 导入本身不需要新权限；v4.2 另加了 `unlimitedStorage`（见下） |

> 1 MB 上限现在只用来限制单次写入体积与启动时的内存占用：v4.2 起改一条只写那一条，不再每次按键序列化整库；权限里加了 `unlimitedStorage` 解除 `storage.local` 的 10 MB 配额。源 `.txt` 文件插件不保管也不删除，含敏感内容的话请自行处理。

## 首次打开就有 8 张便签

你之前给的服务账号预置成 8 张便签，标题是服务名，正文统一三行（`地址：` / `账号：` / `密码：`），Log server 和 Monitor 另带备注：

`pyxis` · `apisix` · `canal` · `laf` · `Alert` · `Monitor` · `Log server（victorialogs）` · `rocketMq`

它们只是普通便签：**想改就改、想删就删**，清空后不会自动补回来。

**如果你在旧版已经录入或改过内容**：启动时会自动把 v1 `sticky.notes.v1` 或 v2 整库 `sticky.workspace.v2` 迁移成 v3 分键布局（一条便签 / 文档一个键 + 一个只存 id 顺序的索引），内容一条不丢，写新键成功后才删旧键。无需手工搬运。

## 数据与安全

| 项 | 说明 |
|---|---|
| 存储 | `chrome.storage.local`，明文。v3 布局：`sticky.workspace.v3` 只存 id 顺序，每条便签 / 文档各占 `sticky.note.v3.*` / `sticky.doc.v3.*` 一个键；内存里的 `WorkspaceFile` 仍是 `{ version:2, notes:[], docs:[] }` |
| 迁移 | v2 整库 `sticky.workspace.v2` / v1 `sticky.notes.v1` 在首次加载时自动拆成分键，写新键成功后才删旧键 |
| 写入时机 | 输入 250ms 节流 + 串行写入队列：同一条连续敲字只写最后一次，不同条目互不覆盖；改一条只写那一个条目键，无保存按钮 |
| 切换 / 关闭 | 切换视图、失焦、页面隐藏 / 关闭前先 flush 待写内容 |
| 写入失败 | 显示**不会自动消失**的「改动没有保存」条幅，内存镜像不更新，直到下次写入成功才清除 |
| 右键保存 | 后台写入 meta + 新便签条目 + 一个很小的 `sticky.selection.v3` 信号键（同一次写入）；界面只监听这个信号键，刷新前先 flush 未落盘的输入 |
| 解锁 | 无，打开即用 |
| 权限 | `storage, sidePanel, unlimitedStorage, contextMenus`（`unlimitedStorage` 只解除 10 MB 配额，`contextMenus` 只注册右键项，均无安装警告）；`host_permissions: []`，不注入页面脚本 |
| 网络 | 零请求。无 `fetch`、无 XHR、无同步、无遥测 |
| 导出 / 备份 | **不提供**。只能从本地 `.txt` 读入，不能把库导出来 |
| 初始数据 | `src/seed/initialNotes.ts`，只在存储键完全不存在时播种一次 |

> 开发预览：用 `npx vite` 起本地服务打开 `sidepanel.html` / `page.html` 时，非扩展环境会自动退化成内存存储，**不会写入真实数据**；扩展内始终使用 `chrome.storage.local`。

## ⚠️ 残留风险（使用前请读完）

1. 便签与文档内容**明文**存本机；能读 Chrome profile 的程序或人可看到全部内容。
2. 本机任何人打开侧栏就能查看、复制、修改、删除，没有任何口令保护。
3. 剪贴板里的内容是明文，可能被其他程序读到。
4. 清 profile / 卸载扩展 = 数据消失，本版**没有导出备份**可用。v4.2 只解决了写入性能与配额，**没有**解决这条边界：分键仍存在扩展沙箱里，换成 SQLite / IndexedDB 也一样会被一起清掉。要真正防丢必须把数据写到扩展之外的磁盘（导出 / 备份），本轮按你的选择没做。
5. 首次播种的 8 张便签含明文密码，也在源码 `src/seed/initialNotes.ts` 和构建产物里；**请勿把这个仓库推到公共远端**。
6. 只放开发 / 测试信息，不要保存个人或生产凭证。
7. 导入的源 `.txt` 是独立的明文文件，插件不保管、不删除；编码识别失败或文件本身是特殊编码时可能得到乱码，导入后请扫一眼正文。
8. debounce 的 250ms 窗口内若浏览器崩溃 / 系统断电，最后一点输入可能来不及落盘；已用失焦、页面隐藏、关闭前 flush 尽量压小窗口。
9. 右键存下的选中文本同样是明文；没有界面打开时保存成功不会有任何提示，保存失败也无法通知。侧栏与全屏页同时打开且都在编辑同一条便签时，仍可能相互覆盖（分键只降低了冲突面，没做跨上下文事务）。

## 已知限制

- 便签与记事本数据不互通，没有「便签转文档」。
- 只支持从本地 `.txt` 读入；不做导出 / 备份 / 同步、不做 Markdown 渲染或 `.md` 导入、自动填充、自动捕获、内容脚本。
- 右键保存只做「一段选中文本 → 一张便签」：不记录来源网址 / 页面标题、不弹窗改标题、不自动打开侧栏；`chrome://` 等受保护页面不显示该菜单项。
- 不做密码生成、强度检测、改密提醒、审计、回收站。
- 只支持 Chromium 本地 unpacked，不支持 Firefox / Safari，不上架商店。
