**用户拍板的 9 个决策**：

3. A3 删除走**两步确认 + 只读统计子树范围**（含 N 个子文件夹 / M 个书签、不可撤销），禁删/移内置根节点（id 0/1/2/3），无撤销无回收站；两个 tab 写入口严格隔离。
4. B1 书签 tab 主视图仍是**域名卡片墙**（与历史 tab 同形不跳变），文件夹降为行上面包屑 + **树形弹层选择器**（兼任「移动到…」目标选择），不引入第二套视图切换。
5. B2 写操作只在**行 hover 菜单**（改名/移动/删除）+ 顶部「+ 新建书签 / 新建文件夹」；卡片右上角只留放大镜，不放卡片级批量删除。
6. B3 **空文件夹统一收进树弹层**管理，卡片墙只渲染有 url 的书签；操作后 toast + 弹层保持打开。
7. C1 书签搜索**纯内存硬过滤**（单字即搜 / 120ms / 多词 AND / 高亮 / 零 API），对齐历史侧域内搜索而非全局搜索；接受与历史全局搜索（≥2 字 / 200ms / 软排序）的手感偏差。
8. D1 **会话内记忆**：`activeTab` 只存模块内存，默认历史，关标签即忘；`?tab=bookmarks` 深链直达；不动零持久化基线、不加 `storage` 权限。
9. E1 设计稿为**全状态静态稿 + 截图**（非可点原型），覆盖两个 tab / 域内作用域 / 树弹层 / 行级菜单 / 两步确认条 / 详情页 / 空态。

## 实现前 API 核对（Chrome 官方 bookmarks 文档，2026-11-17）

- 权限名 `bookmarks`。`BookmarkTreeNode` 字段：`id` / `parentId`（根节点省略）/ `index` / `title` / `url`（**文件夹省略**）/ `dateAdded` / `dateGroupModified` / `dateLastUsed`（Chrome 114+，非文件夹）/ `children`（文件夹）/ `folderType`（Chrome 134+，枚举 `bookmarks-bar|other|mobile|managed`）/ `unmodifiable: "managed"` / `syncing`。
- **修正 A3 的「禁动内置根节点 id 0/1/2/3」硬编码方案**：官方明确「不能在根文件夹新增或移除项目；不能重命名 / 移动 / 移除『书签栏』和『其他书签』」，但 `folderType: "mobile"` 的移动端书签**可被扩展修改**。因此锁定判定应基于 `folderType` 存在 + `unmodifiable === 'managed'` + 无 `parentId` / `id === '0'`，而非硬编码四个 id 全锁。`ROOT_NODE_ID = "0"` 常量要 Chrome 145+ 才有，不要依赖。
- `create()` 省略 `parentId` 时默认落到「其他书签」；文件夹节点靠「无 url」识别；受管节点（`unmodifiable`）一律不可写。
- `dateLastUsed` 是「上次打开时间」的备选，但定稿排序仍用 `dateAdded`，不额外引入。
- 写操作均为 Promise（MV3，Chrome 90+），无需 callback 包装。

## site-keys / v4.3 网页选中文本右键存为便签（已实现）

需求：浏览器中选中文本 → 右键「存为便签」→ 生成一张便签。版本 0.4.2 → **0.4.3**。

**关键事实（已核对）**：`contextMenus` + `contexts: ['selection']` 的 `OnClickData.selectionText` 由浏览器在右键时直接提供，**不需要 host_permissions / 内容脚本 / activeTab / scripting / tabs.sendMessage**；MV3 service worker 中 `create()` 的 `onclick` 不可用，只能用 `contextMenus.onClicked`；菜单项属于扩展而非 worker，必须在 `runtime.onInstalled` 里 `removeAll()` → `create()` 注册一次，顶层重复 create 会 duplicate id 报错。`contextMenus` 权限无安装警告。

**架构决策（下次别走回头路）**：
- 后台直接写 v3 正式分键（不设收件箱中转键），但**每次先 `loadWorkspace()`** 让 v2/v1 旧库完成迁移，否则新 meta 会挡住旧数据；`createSelectionSaver()` 用串行 Promise 队列防止连续右键的读-改-写互相覆盖。
- 界面与后台之间用**一个很小的信号键** `sticky.selection.v3`（与 meta + 条目同批原子写），UI 只监听这一个键。不用 `runtime.sendMessage`（页面未开/加载中送不到、无接收者会报错），**更不能用全量 `storage.onChanged`**（会把刚做好的增量写退化成每次输入后全量读盘）。
- 收到信号先 `flushWrites()` → `await pending` → `controller.reload()` → `syncFromController()`，否则会覆盖用户正在敲、还没到 250ms debounce 的字；详情浮层 draft 需重新绑定到新数组对象。
- 全新安装且从未打开界面时右键保存 **不补播 8 张示例便签**（有意选择，写进文档）。

**改动**：新增 `src/core/selection.ts`；重写 `src/background/index.ts`（第三件事）；`useWorkspace.ts` 加 `reload()`；`App.vue` 抽出 `syncFromController()` + 信号监听；`core/index.ts` 导出；`public/manifest.json` 加 `contextMenus`（第 4 项）；新增 `tests/selection.test.ts` 19 例，并修订 manifest / security / import / incremental 四处旧权限断言。顺手校正 SPEC §2 / §7.4 / §9 / §10 里沿袭的「两项权限」历史描述。文档同步 SPEC / README / TICKETS（T-41 + 偏差 15~17）/ 根 README / 图标预览版本标签。

**验收**：12 文件 / **158 用例全绿**，`typecheck` 零错误，`build` 成功，产物审计无 `fetch` / `executeScript` / `window.getSelection` / `<all_urls>`；主 JS 89.16 KB + 共享 chunk 5.16 KB + background 0.7 KB，合计约 95 KB / 35.7 KB gzip，无新依赖。真实浏览器注入假扩展 API、加载真实 `background.js` 与侧栏产物：三次 onClicked → 便签 8→9→10→11、toast 出现、编辑中未落盘内容仍在磁盘上。**真机系统右键菜单手工验收仍未执行**。

## history-by-domain / §16.13 修订：书签改为「按文件夹排列」（同日，用户反馈后）

**用户反馈原话**：`做的有点不对劲啊，没按照书签文件夹排列吗，看着是按域名排的，那样我不太方便找内容`。
**根因**：v1.3.0 为追求「两个 tab 同形」，把书签也按 `regDomain` 聚合成卡片，与用户「按自己整理的文件夹找内容」的心智相反。早期 B1/B3 决策与 s02 设计稿因此作废。

**用户选择**：三选一里挑了「**文件夹卡片墙**」（每个卡片 = 一个文件夹，卡片内只放直属书签，子文件夹作为可点入口；改动最小）。另两案「左树 + 右列表」「域名/文件夹二级切换」未采纳。

**新契约（SPEC §16.13，优先级高于 §16.1–§16.12）**：
- 一张卡片 = 一个书签文件夹；排除虚拟根 `id '0'`；顺序 = **Chrome 书签树前序**（用户自己排的顺序），**不按 dateAdded 倒序**。历史 tab 仍按域名聚合，零回归；**两个 tab 不再同形**。
- 卡片头：文件夹图标 + 文件夹名 + 完整路径面包屑 +「N 个书签 · M 个子文件夹」+ 放大镜 + **卡片头 hover 菜单**（改名 / +子文件夹 / 删除，内置锁定节点禁用改名与删除）。
- 卡片内**只放直属书签**（`parentId === folder.id`），不递归；行内第二行由「文件夹面包屑」改**显示域名**（文件夹信息已在卡片头）。
- 子文件夹 chips → 进入该文件夹作用域；**空文件夹显示为空卡片**（修订 B3）；**不再有「本地 / 其他」域名桶**，特殊协议书签留在所属文件夹内只展示不打开。
- 作用域：`scopeKey` 改存 **folderId**，候选 = `subtreePages()` 递归含所有子文件夹；chip「仅在文件夹『X』内搜索书签」+「含所有子文件夹」。
- 详情页 `detail.html?source=bookmarks&folder=<id>`，标题为文件夹完整路径，含所有子文件夹，只读；`domain=` 兼容分支保留。

**实现要点**：
- `bookmarks.js` 新增 `folderPathOf` / `subtreePages` / `aggregateFolders`（内部 `folderCounts` 一次算直属数与递归数，避免 O(n²)）；保留 `aggregateBookmarks` 不影响历史侧。
- 修掉 `flatten` 的真实健壮性问题：`parentId` / `folderPath` **改由遍历推导**，不依赖源节点是否带齐字段；`isLocked(node)` 也在补字段后判定。

## history-by-domain / 卡片头工具组「默认常显」根治（同日第六次反馈）

**用户反馈**：`你改的啥，像话吗，默认就一个搜索框在一个中不中，边不边的位置，能不能用点心，顶部4个按钮，怎么安排定位才合理，多想想`，随后补一张截图 `我说这里`，橙色框圈定**卡片头右上角约 105px 区域**（不是页面顶栏）。

**根因（用 CDP 渲染真实 index.html 默认态实测坐实，不是靠猜）**：上一轮只把三个管理图标的 DOM 挪进 `.card-tools`，但 `.bm-folder-ops` 仍是 `opacity: 0`（hover 才出现）。实测默认态 `opsOpacity: "0"`、`scopeOpacity: "0.38"`、工具组 `topGap: 26px`（垂直居中于两行文字之间）。所以用户看到的仍是「一个半透明放大镜 + 右侧约 78px 空白」，悬在半空、不贴边 —— 改了等于没改。

**三条定位原则（SPEC §16.13.1 已固化）**：
1. **默认常显**：四枚图标一律 `opacity: 1`，hover 只用于提亮/着色，绝不用于显隐。这是本次最关键的修复。
2. **贴右上角、顶部对齐**：`.card-tools { align-self: flex-start; margin-top: 4px }`，与 32px 文件夹图标同一水平带；距卡片右边缘 17px。
3. **1 + 3 语义分组**：放大镜（只读查看）｜改名 / 新建子文件夹 / 删除，中间 1px 竖线 + 6px 间距；删除固定最右、淡红；三层反馈「默认中灰 → hover 卡片提亮 → hover 单按钮着色」；默认无边框无底色避免常显显杂；禁用态 `opacity: .3`。

**踩过的坑**：新写的默认色规则特异性 (0,3,0) 高于原有 `.bm-op:hover` / `.card-scope:hover` (0,2,0)，会把单按钮 hover 反馈盖掉；必须显式补 `.card--bm .bm-folder-ops .bm-op--icon:hover:not(:disabled)` 与放大镜 hover 规则。

**窄卡片验证**：用 CDP 改视口宽度实测 1400 / 820 / 340px（卡片 324 / 374 / 308px），四枚图标 `iconTops` 全部相同（同行）、`toolsOverlapDomain: false`、标题区 105px 时仍未截断。用户截图那种约 250–300px 卡片也稳。

**同步**：`styles.css`、`design/mockup.html`（去掉 `#s02 .bm-folder-ops{opacity:1}` 强制展开特例，所有画板默认常显 + 分组线 + 顶对齐 + 4 处文案）、`SPEC.md` §16.13.1 三条原则 + 验收 59、e2e 断言升级为「默认透明度 1/1 + 贴顶 + 分隔线 1px + 距右 < 24px」。重跑 `shot.mjs`：preview 1480×9276，10 张裁图，重叠检查通过。

**验收**：11 个 JS 语法 OK；纯逻辑 10 组新 + 5 组旧全过；端到端 **44 组**全过；圆角仍 4px×22 / 3px×2 / 2px×1 / 50%×2 / 999px×3；设计稿零脚本零外链；CRLF/LF 保持。

**经验**：`opacity: 0` 隐藏 hover 工具栏后，即便 DOM 位置调对了，默认视角仍等于没改。改布局前先渲染**真实默认态**（不带 hover）截图核对，别只看设计稿 —— 设计稿里往往有强制展开特例，会掩盖这个问题。
