## 网迹 v1.5.1：顶栏顺序改为「标签页 / 书签 / 历史」，默认落点改标签页

- **用户诉求**：标签页管理最常用，放第一个；历史放最后。原始需求是「调整 tab 顺序」。
- **判断**：只调顺序不改默认落点会形成矛盾态（第一个按钮不亮、第三个亮），所以两处一起对齐；标签页也是 `state.activeTab` 初值。
- **连带必须改的点**：`init()` 原来无条件先读 90 天历史首屏（为深链直达书签后切回历史有数据）。默认视图改成标签页后这次读取纯浪费。抽出 `ensureHistoryFirstScreen()` + `state.historyReady`，只读一次；深链 `?tab=history|bookmarks` 仍预读；非法 `?tab` 值回落标签页。
- **`switchTab` 新增 `{ force }`**：`state.activeTab` 初值已是 `'tabs'`，否则 init 里 `switchTab('tabs')` 被「同 tab 直接返回」挡掉，标签页面板根本不会激活。这是本次最容易踩的坑。
- **实测（Playwright 加载真实扩展，包住 `chrome.history.search` 计数）**：启动到切走前 0 次调用；首次切历史 1 次出 2 卡；切走再切回仍 1 次；`?tab=history` / `?tab=bookmarks` 直达正常，`?tab=乱写` 回落标签页。
- **测试**：`tests/nav-order.test.mjs` 5 条静态断言，锁「控件顺序 / 初始显隐 / activeTab 初值 / history 懒加载」四者一致。单测 27 条全过。
- **环境**：playwright 用 `D:/Project/emr-ai-devtools/node_modules/playwright`，chromium 必须是 `~/.AppData/Local/ms-playwright/chromium-1228/chrome-win64/chrome.exe`（1228 是 win64 目录，写成 chrome-win 会报 executable doesn't exist）。
- **遗留观察（未改）**：地址栏 `h 关键词` 走 `?q=`，现在会搜当前/默认 tab（默认即标签页）。语义是「作用于当前 tab」，面板已开着时也一样，行为自洽；若用户希望它固定搜历史，需在 `sw.js` 里加 `&tab=history`。

## 网迹 v1.5.2：修标签页行悬浮高亮只亮一半

- **现象**：悬浮行时浅底纹只铺到操作按钮左侧，右侧按钮区保持白色，像被切断。
- **根因**：高亮写在 `.card--tabs .tab-focus` 上，而它是 `flex: 1 1 auto` 只占标题列；右侧 `.tab-ops` 是兄弟节点。v1.5.0 把「全部关闭」换成悬浮图标按钮时，行内结构从「整行可点」变成「标题按钮 + 操作区」，高亮没跟着挪到 `li`。
- **修法**：背景与过渡挪到 `li.tab-row`；`.tab-focus:hover` 只保留文字变色；补 `li:focus-within` 让键盘聚焦同形。
- **实测**：移出透明 → 悬停 `rgb(247,249,253)`，li 横向 45→375 覆盖 `.tab-focus`(47→317) 与 `.tab-ops`(323→373)；悬停到按钮上背景保持；键盘聚焦同色。
- **回归网**：`tests/wiring.test.mjs` 加一条 CSS 落点断言（hover/focus-within 必须命中 li；`.tab-focus:hover` 不得写 background）。单测 28 条全过。

## 网迹 v1.5.3：标签页批量关闭去掉二次确认

- **诉求**：用户嫌「点 2 次太麻烦」，要求卡头组级「全部关闭」的确认条也去掉。
- **改动**：三条写路径（组级全部关闭 / 行级关闭其他 / 单条）统一一次点击即执行；删掉 `.del-bar` DOM、`state.pending`、`tabs-cancel` / `tabs-confirm` 处理器，`isBusy()` 只反映关闭在途。`tabs.js` 的 `confirmText` 换成 `closeToast(target)`（关几个 / 固定页保留几个 / Ctrl+Shift+T 可恢复），爆炸半径改由 toast 交代；关闭前仍按最新 `chrome.tabs.query()` 重算目标。
- **顺带修掉隐性死按钮**：v1.5.0 把分组口径从 regDomain 改成 host 后，`tab-close-others` 仍用 `item.regDomain` 当 pending key，与卡片 key（host）对不上 → 确认条永不显示、点了既不确认也不关闭。改成直接执行后该缺口消失（e2e 实测 id 6 被关、id 5 保留）。
- **验证**：`tests/tabs.test.mjs` 两条 closeToast 断言 + `tests/wiring.test.mjs` 一条「不再渲染确认条」静态断言，单测 29 条全过；Playwright + mock chrome.tabs 跑真实 index.html，8 条实测全过（点击后 `.del-bar` 数为 0、`tabs.remove` 立即调用且跳过固定页、toast 文案正确）。
- **书签侧不动**：删除确认条（`.del-bar` 样式与 bookmarks-panel）完全保留，卡片 pending 边框仍是书签用。
