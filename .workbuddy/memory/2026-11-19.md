# 2026-11-19

## 网迹 v1.5.1：顶栏顺序改为「标签页 / 书签 / 历史」，默认落点改标签页

- **用户诉求**：标签页管理最常用，放第一个；历史放最后。原始需求是「调整 tab 顺序」。
- **判断**：只调顺序不改默认落点会形成矛盾态（第一个按钮不亮、第三个亮），所以两处一起对齐；标签页也是 `state.activeTab` 初值。
- **连带必须改的点**：`init()` 原来无条件先读 90 天历史首屏（为深链直达书签后切回历史有数据）。默认视图改成标签页后这次读取纯浪费。抽出 `ensureHistoryFirstScreen()` + `state.historyReady`，只读一次；深链 `?tab=history|bookmarks` 仍预读；非法 `?tab` 值回落标签页。
- **`switchTab` 新增 `{ force }`**：`state.activeTab` 初值已是 `'tabs'`，否则 init 里 `switchTab('tabs')` 被「同 tab 直接返回」挡掉，标签页面板根本不会激活。这是本次最容易踩的坑。
- **实测（Playwright 加载真实扩展，包住 `chrome.history.search` 计数）**：启动到切走前 0 次调用；首次切历史 1 次出 2 卡；切走再切回仍 1 次；`?tab=history` / `?tab=bookmarks` 直达正常，`?tab=乱写` 回落标签页。
- **测试**：`tests/nav-order.test.mjs` 5 条静态断言，锁「控件顺序 / 初始显隐 / activeTab 初值 / history 懒加载」四者一致。单测 27 条全过。
- **环境**：playwright 用 `D:/Project/emr-ai-devtools/node_modules/playwright`，chromium 必须是 `~/.AppData/Local/ms-playwright/chromium-1228/chrome-win64/chrome.exe`（1228 是 win64 目录，写成 chrome-win 会报 executable doesn't exist）。
- **遗留观察（未改）**：地址栏 `h 关键词` 走 `?q=`，现在会搜当前/默认 tab（默认即标签页）。语义是「作用于当前 tab」，面板已开着时也一样，行为自洽；若用户希望它固定搜历史，需在 `sw.js` 里加 `&tab=history`。
